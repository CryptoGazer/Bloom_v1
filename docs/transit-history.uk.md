# Історія транспорту: що змінено в мобільній версії

Оновлено 15.11.2026. Сервер знає, як лінія реально ходила в недавній день (дані з Tiger Data), і мобільна версія це вже показує. Цей файл — щоб було зрозуміло, що саме з'явилося у `web/m/`.

## Що видно на екрані

На екрані поїздки, під живою карткою рейсу, одна фраза з порадою:

> Вчора о цій порі трамвай 8 йшов на ~3 хв раніше розкладу. **Будьте на зупинці за 4 хв.**

За натисканням розкривається рядок із джерелом: скільки рейсів, за який час, якого дня, і що це спостереження, а не обіцянка. Якщо даних немає, блоку немає.

## Звідки дані

У відповіді `/api/route?mode=transit`, у кроці поїздки (`type: "ride"`), є поле `history`. Якщо даних немає, воно дорівнює `null`.

```json
"history": {
  "day": "2026-11-14", "when": "yesterday", "from": "22:30", "to": "01:00",
  "trips": 4, "median_min": -2.6, "early_min": -3.5, "late_min": -1.1,
  "pattern": "early", "be_early_min": 4, "wait_up_to_min": null, "last_seen": "23:59"
}
```

`/api/health` показує `"history": true`, коли історія прочитана з бази.

## Правила, які треба зберегти

- **Жива картка рейсу головніша.** Історія йде нижче й дрібніше.
- **Порада лише в один бік.** Є «прийдіть раніше» і «може запізнитися». «Можна вийти пізніше» не пишемо ніколи.
- **Джерело завжди доступне:** день, число рейсів, «це не обіцянка».
- **Розрахунок маршруту не змінюється.** Час «вийти о…» лишається таким самим.

## Як перевірити

Зараз у базі є вечір 14.11 (з 21:09 до 00:08) і дані з 15.11, які збирає сервер. Для поїздки, на час якої даних ще немає, `history` буде `null`.

```
http://localhost:8001/m/?lang=ru#a=45.74717,21.24669&b=45.74441,21.22243&m=transit&at=2026-11-15T23:20
```

Повний опис: `docs/transit-history.md`.
