# Gemini в Bloom: интеграция блока текстового и голосового ввода в новый интерфейс

Документ для передачи разработчику интерфейса. Он описывает фактический контракт текущего backend и то, как UI должен применять результат. Актуальные реализации: `backend/ask.py`, endpoint в `backend/app.py`, существующий клиент в `web/ask.js`.

Production: `https://bezna.xyz`. В интерфейсе, который раздаётся с того же домена, нужно использовать относительные URL (`/api/health`, `/api/ask`), а не зашивать production-hostname.

Обновление 15.11.2026: общий `web/ask.js` обслуживает и десктоп, и мобильный `/m/`. Добавлены закреплённые модели, повторный разбор через Flash, каталог мест с алиасами, Function Calling и выбор кандидатов. Повторный аудит добавил исходные фразы A/B, приближённые подсказки, сохранение кандидатов при ошибке модели и очистку старого маршрута. Подробности ниже в разделах 5.5 и 9; обзор для решения о коммите — `docs/gemini-review.ru.md`.

После слияния интерфейса Тимура общий `BzAsk` в `web/ask.js` отвечает за доступность, HTTP-запрос и запись/WAV. Десктопный обработчик ответа находится в том же файле, мобильный — в `web/m/m.js` (`askApply`, `askCard`). Оба поддерживают полный контракт уточнений. На `/m/` запрос открывается с главного экрана в отдельной панели; старой Gemini-формы в поиске адресов больше нет.

Следующее обновление, `ask_version: 3`: Gemini поддерживает замкнутые прогулки вокруг места, включая «обойди центр». Новый ответ `kind: loop` описан в разделе 5.6. Точки для круга подбирает сервер по доступной дорожной сети, затем используется тот же `/api/loop`, что и для ручной прогулки.

Обновление `ask_version: 4`: круг через несколько мест возвращает `points: Place[]` в заданном порядке вместо центра. Все точки передаются в `/api/loop?points=...`; такой ответ не должен сводиться к A → B. При неизвестной точке `kind: clarify` сохраняет массив с `null` на её позиции и `point_issues: [{index, query, candidates}]`. Выбор кандидата/обычный поиск заменяет только эту позицию без повторного Gemini. Общий круг без места использует Piața Libertății.

Обновление доставки UI: `ui_version` в `/api/health` совпадает с заголовком HTML `X-Bezna-UI-Version` и параметром `?v=` у JS/CSS. При изменении скрипта меняются ссылки и ETag HTML, даже если сама разметка не менялась. HTML/JS/CSS перепроверяются через `Cache-Control: no-cache`, API отдаёт `no-store`.

## 1. Что делает и чего не делает Gemini

Gemini здесь не является чат-ботом и не строит маршрут. Он выполняет одну ограниченную задачу: превращает текст или голос человека в форму:

```json
{
  "intent": "route",
  "from": "Căminul C12",
  "from_here": false,
  "to": "Piața Victoriei",
  "mode": "bike",
  "time": "2026-11-14T23:30",
  "heard": ""
}
```

После ответа Gemini backend:

1. Проверяет допустимые значения и длину полей.
2. Ищет распознанные названия только в локальном `places.json.gz`.
3. Возвращает UI доверенные точки с координатами.
4. Сам маршрут по этим точкам по-прежнему считает обычный Bloom routing API.

Полный flow:

```text
текст или микрофон
        ↓
POST /api/ask
        ↓
Gemini: intent + названия + режим + время
        ↓
локальный поиск мест Bloom
        ↓
kind: route + доверенные координаты
        ↓
UI заполняет A/B, режим и время
        ↓
обычный пересчёт /api/route
```

ElevenLabs в этом flow не участвует. Голосовая запись отправляется напрямую в Gemini как аудиовход. ElevenLabs можно позднее применить отдельно для озвучивания результата.

## 2. Требования к размещению нового UI

Рекомендуемый вариант: новый интерфейс раздаётся тем же FastAPI/Caddy и работает на том же origin, что и API. Тогда запросы выглядят так:

```js
fetch('/api/health')
fetch('/api/ask', { method: 'POST', ... })
```

Если UI будет размещён на другом домене или dev-server, backend сейчас не настраивает CORS. В таком случае либо проксировать `/api` на Bloom из dev-server, либо отдельно согласовать CORS. Нельзя вызывать Google Gemini напрямую из браузера: это раскроет `GEMINI_API_KEY`.

Микрофон браузера работает только в secure context: HTTPS или localhost. Production уже доступен по HTTPS.

## 3. Проверка доступности функции

При инициализации блока:

```http
GET /api/health
```

Пример ответа:

```json
{
  "ok": true,
  "segments": 5405,
  "data_as_of": "2026-11-14",
  "ask": true
}
```

Правило UI:

- `ask: true` — показать Gemini-блок;
- `ask: false` — скрыть его, но оставить обычные поля From/To;
- ошибка healthcheck — основная форма маршрута продолжает работать без Gemini.

Текущий healthcheck возвращает `ask_version: 4`. Версия `3` ещё не поддерживает список мест в круге. Версия `2` ещё не умеет круговые прогулки Gemini. Отсутствие поля означает более старую запущенную версию backend, даже если файлы frontend на диске уже обновились. После изменения Python-кода нужен перезапуск процесса или локальный `uvicorn --reload`.

`ask` становится `true`, только если backend нашёл одновременно ключ Gemini и локальный индекс мест.

## 4. Endpoint и тело запроса

```http
POST /api/ask
Content-Type: application/json
```

Тело:

```ts
type AskRequest = {
  text?: string;   // текст запроса, максимум 300 символов
  audio?: string;  // чистый base64 без префикса data:...
  mime?: string;   // для текущего UI: audio/wav
  lang?: 'ro' | 'en' | 'ru';
  near?: string;   // текущая точка A в формате "lat,lon"
};
```

Нужно отправлять либо `text`, либо `audio`, но не оба сразу. Если присутствует `audio`, backend обрабатывает запрос как голосовой.

### Текстовый пример

```js
const response = await fetch('/api/ask', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    text: 'от Căminul C12 до Piața Victoriei на велосипеде',
    lang: 'ru',
    near: currentStart ? `${currentStart.lat},${currentStart.lon}` : '',
  }),
});
```

### Для чего нужен `near`

`near` — уже выбранная пользователем точка старта. Backend использует её локально, например чтобы найти ближайшую аптеку в запросе «отсюда до ближайшей аптеки».

Координата `near` не отправляется Gemini. В Gemini уходят текст или аудио, язык и локальное время, а также публичные имена мест, их непрозрачные ID и алиасы. Ответы поисковых функций содержат только ID, имя и тип места, без координат.

Формат:

```text
45.74720,21.23140
```

Не нужно отправлять объект, GeoJSON или порядок `lon,lat`.

## 5. Варианты успешного ответа HTTP 200

### 5.1 `kind: route`

```ts
type Place = {
  kind: string;
  name: string;
  lat: number;
  lon: number;
  nearest_of?: string;
};

type AskRoute = {
  kind: 'route';
  from: Place | null;
  from_here: boolean;
  to: Place;
  mode: 'walk' | 'bike' | 'transit' | null;
  at: string | null;       // YYYY-MM-DDTHH:MM, иногда legacy HH:MM
  heard: string;           // только для голоса, максимум 500 символов
};
```

Пример:

```json
{
  "kind": "route",
  "from": {
    "kind": "place",
    "name": "Căminul C12 UVT",
    "lat": 45.7498,
    "lon": 21.2403
  },
  "from_here": false,
  "to": {
    "kind": "street",
    "name": "Piața Victoriei",
    "lat": 45.7531,
    "lon": 21.2257
  },
  "mode": "bike",
  "at": "2026-11-14T23:30",
  "heard": ""
}
```

Действия UI в указанном порядке:

1. Если `mode !== null`, выбрать соответствующий режим.
2. Если `at !== null`, заполнить время отправления.
3. Всегда установить точку B из `to.lat`, `to.lon`, `to.name`.
4. Если `from !== null`, установить точку A из `from`.
5. Если `from === null`, применить правила старта ниже.
6. Запустить обычный пересчёт маршрута.

Правила, когда `from === null`:

| Ситуация | Действие |
|---|---|
| Уже есть выбранная A, `from_here === false` | Оставить существующую A |
| `from_here === true` | Запросить/использовать текущую геолокацию |
| A ещё нет и старт не назван | Запросить текущую геолокацию |

`mode: null` означает «режим не был назван»: UI не должен самовольно менять уже выбранный режим.

`at: null` означает «время не было названо»: сохранить текущее состояние формы. Для маршрута «сейчас» route API сам использует текущее время.

### 5.2 `kind: off_topic`

```json
{
  "kind": "off_topic",
  "heard": ""
}
```

Используется для рецептов, программирования, общих вопросов, других городов, prompt injection и просьб раскрыть инструкции.

UI не должен показывать сгенерированный Gemini-текст. Рекомендуемый локальный текст:

```text
Я строю только маршруты по Тимишоаре. Напишите или скажите, откуда и куда вам нужно.
```

### 5.3 `kind: unclear`

```json
{
  "kind": "unclear",
  "heard": ""
}
```

Маршрутная тема понятна, но destination распознать нельзя, либо запись непонятна.

Рекомендуемый текст:

```text
Не понял, куда вам нужно. Например: «от Căminul C12 до Piața Victoriei».
```

### 5.4 `kind: not_found`

Не найден старт:

```json
{
  "kind": "not_found",
  "which": "from",
  "name": "Несуществующее место",
  "heard": ""
}
```

Не найден destination, но старт уже найден:

```json
{
  "kind": "not_found",
  "which": "to",
  "name": "Несуществующее место",
  "from": {
    "kind": "place",
    "name": "Căminul C12 UVT",
    "lat": 45.7498,
    "lon": 21.2403
  },
  "heard": ""
}
```

Действия UI:

1. Если в ответе есть `from`, применить его как точку A.
2. Записать `name` в проблемное поле `from` или `to`.
3. Сфокусировать это поле и открыть обычные локальные подсказки.
4. Показать сообщение, что место не найдено внутри области карты.

### 5.5 `kind: clarify` и расширенный ответ об уточнении

Ответы `clarify`, `unclear` и `not_found` сохраняют уже найденные `from`, `to`, `mode`, `at`, `from_here` и `heard`. Дополнительные поля:

```ts
type AskClarification = {
  kind: 'clarify' | 'unclear' | 'not_found';
  from: Place | null;
  to: Place | null;
  from_here: boolean;
  mode: 'walk' | 'bike' | 'transit' | null;
  at: string | null;
  heard: string;
  which: 'from' | 'to';
  name: string | null;
  missing: ('from' | 'to')[];
  ambiguity: ('from' | 'to')[];
  candidates: { from: (Place & {id: string})[]; to: (Place & {id: string})[] };
  queries: { from: string | null; to: string | null }; // исходные названия до исправления моделью
};
```

`missing` — какие точки нужно назвать/найти; `ambiguity` — для каких описаний нужна проверка пользователем. Отсутствующий старт обычно означает геолокацию и сам по себе не считается missing. «Две случайные точки» возвращает missing для обеих сторон; приложение не выбирает произвольные места.

UI сначала сохраняет известные точки/режим/время, затем выводит кнопки `candidates` в блоке `#ask-choices`. Названия вставляются через `textContent` на десктопе, через HTML-экранирование `esc()` в мобильной панели. Нажатие локально заполняет соответствующую сторону, убирает её из missing/ambiguity и предлагает уточнить оставшуюся. После выбора всех необходимых точек запускается обычный `/api/route`. Для выбора кандидата повторный `/api/ask` не нужен. Если кандидатов нет, десктоп фокусирует обычное поле From/To; мобильная версия показывает кнопку проблемной точки, открывающую поиск с исходным запросом. Обработчики ответа — в `web/ask.js` и `web/m/m.js`, мобильные стили — в `web/m/index.html`.

Перед применением маршрутного ответа UI сбрасывает старую геометрию и отбрасывает запоздавшие ответы предыдущего `/api/route`. Стороны с missing/ambiguity очищаются вместе с их старыми координатами. Если B уже найдена, она применяется независимо от ошибки A. Ручное поле заполняется из `queries[which]`, чтобы пользователь видел своё исходное название, а не выдуманное исправление. При `from_here: true` старая A сбрасывается перед запросом геолокации. Оба обработчика используют свои `clearPoint` и `clearAskRoute` с одинаковым смыслом. Отмена мобильного запроса или переход к круговой прогулке исключает применение запоздавшего ответа.

### 5.6 `kind: loop`: замкнутая прогулка вокруг места

Примеры: «обойди центр Тимишоары», «небольшой круг вокруг Ботанического парка», «a circular walk around me, from here and back», «un circuit cu bicicleta în jurul căminului C12».

```json
{
  "kind": "loop",
  "loop": true,
  "to": {"kind": "place", "name": "Parcul Botanic", "lat": 45.760166, "lon": 21.224805},
  "from": null,
  "from_here": false,
  "mode": "walk",
  "at": null,
  "radius_m": 200,
  "heard": ""
}
```

Здесь `to` — **центр прогулки**, а не её конечная точка. Для исторического центра ориентир по умолчанию — локально найденная Piața Libertății. Модель не выдаёт координаты обхода: backend проверяет место по индексу. Если центр неоднозначен, обычные `clarify`/`not_found`/`unclear` сохраняют `loop: true` и `radius_m`; интерфейс после уточнения продолжает строить круг, в том числе при выборе места обычным поиском.

Далее оба клиента вызывают `BzAsk.loopParams(response)`, добавляют режим/время и отправляют:

```http
GET /api/loop?center=45.760166,21.224805&radius_m=200&mode=walk
```

Если задан явный старт, добавляется `start=lat,lon`; при `from_here` перед этим запрашивается геолокация. Для «вокруг меня» `to` может быть `null`: полученная позиция становится и центром, и стартом. Простое «вернись к началу» не включает геолокацию и не назначает старт в центре. Без заданного старта круг начинается в первой подобранной точке на улице.

`backend/loops.py` подбирает 4–8 точек на связной сети нужного режима вокруг центра; отдельный старт может добавить девятую. Точки обходятся в угловом порядке. При нехватке покрытия пробуются меньшие радиусы и другой поворот. Маршрут замыкается через существующий `Network.loop`, со стандартными быстрым и более освещённым вариантами. Замкнутая прогулка может повторять отдельные улицы; геометрически идеальный круг не обещается.

Радиус по умолчанию — 400 м, для «небольшой/короткой» — 200 м, для большой — 700 м. При явно указанной длине/длительности Gemini оценивает радиус. Разрешённый диапазон — 100–1200 м. Фактические длина и время считаются по улицам и показаны на карточках; они не гарантированно совпадают с запрошенной оценкой. Автоматический ответ дополнительно содержит `generated: true`, `center`, `requested_radius_m`, фактически использованный `radius_m` и `points`.

Кандидаты и ручное уточнение центра не требуют повторного Gemini. Повторное открытие ссылки сохраняет выбранные точки. В мобильной версии точки можно дальше менять как в обычной круговой прогулке.

Ограничения и ошибки:

- Круг на общественном транспорте возвращает `kind: unsupported, reason: loop_transit`; UI предлагает пешком или велосипед, а не меняет способ молча.
- Если вокруг центра нельзя подобрать разумный обход, `/api/loop` возвращает 422 с `detail.code: no_loop_area`. UI показывает перевод `ask.loopUnavailable`, без старого маршрута.
- Старт вне доступной сети даёт `outside_coverage`. Направления движения и ограничения велосипеда учитываются тем же графом, что у обычной маршрутизации.
- Запросы «до центра» продолжают строить обычный A → B; рецепт или программирование остаются `off_topic`.

## 6. Голосовой ввод

Текущая реализация использует браузерные `getUserMedia` и `MediaRecorder`.

Кнопку микрофона показывать только если одновременно доступны:

```js
navigator.mediaDevices?.getUserMedia &&
window.MediaRecorder &&
window.isSecureContext
```

Рекомендуемые параметры записи:

```js
await navigator.mediaDevices.getUserMedia({
  audio: {
    channelCount: 1,
    echoCancellation: true,
    noiseSuppression: true,
  },
});
```

Текущий клиент:

1. Записывает не более 10 секунд.
2. Декодирует браузерный WebM/Opus или MP4/AAC через `AudioContext`.
3. Ресемплирует через `OfflineAudioContext`.
4. Создаёт mono PCM WAV, 16 bit, 16 kHz.
5. Проверяет peak: запись с peak ниже `0.02` считается тишиной и не отправляется.
6. Кодирует все байты WAV в base64.

Запрос:

```js
await fetch('/api/ask', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    audio: wavBase64,
    mime: 'audio/wav',
    lang: currentLanguage,
    near: currentStart ? `${currentStart.lat},${currentStart.lon}` : '',
  }),
});
```

В `audio` нельзя передавать строку вида:

```text
data:audio/wav;base64,UklGR...
```

Нужна только часть после запятой:

```text
UklGR...
```

Backend также принимает MIME:

```text
audio/wav
audio/x-wav
audio/webm
audio/ogg
audio/mp4
audio/mpeg
audio/aac
audio/flac
```

Но готовый существующий converter отправляет `audio/wav`, поэтому для нового UI лучше сохранить этот формат.

## 7. `heard` и UX голосового запроса

Для голоса Gemini возвращает расшифровку в `heard`, например:

```json
{
  "heard": "от общежития C12 до площади Победы на велосипеде"
}
```

Её можно показать перед результатом:

```text
Услышал: «…». Понял: Căminul C12 UVT → Piața Victoriei · велосипед.
```

Для текста backend принудительно возвращает `heard: ""`, даже если модель попыталась его заполнить. Нельзя использовать `heard` как главный источник названий или координат — применять нужно только доверенные `from` и `to`.

## 8. Ошибки HTTP

Ошибки приложения обычно имеют форму:

```json
{
  "detail": {
    "code": "too_many",
    "message": "too many requests, try again in a minute"
  }
}
```

Для ошибок провайдера backend специально скрывает внутреннюю причину и API key из публичного ответа. Причина остаётся только в server log.

| HTTP | `detail.code` | Значение | Действие UI |
|---:|---|---|---|
| 422 | `empty` | Нет текста и аудио | Не отправлять пустую форму |
| 422 | `too_long` | Текст длиннее 300 символов | Ограничить input через `maxlength=300` |
| 422 | `bad_audio` | MIME, base64 или размер аудио не прошли проверку | Предложить записать ещё раз или ввести текст |
| 422 | `bad_point` | Некорректный `near` | Исправить сериализацию текущей точки |
| 429 | `too_many` | Превышен rate limit | Попросить повторить через минуту |
| 503 | `ai_busy` | Квота/перегрузка всех моделей | Оставить обычные From/To доступными |
| 503 | `ai_not_configured` | Нет/не принят key или нет индекса мест | Скрыть/отключить Gemini-блок |
| 502 | `ai_unavailable` | Сетевая или provider-ошибка | Показать fallback, не ломать форму маршрута |

FastAPI/Pydantic также может вернуть стандартный массив `detail` для нарушения максимальной длины JSON-полей. Обработчик ошибок должен выдерживать как объект с `detail.code`, так и неизвестную структуру.

## 9. Лимиты и поведение backend

| Ограничение | Значение |
|---|---:|
| Текст | 300 символов |
| Голос в текущем UI | 10 секунд |
| Поле base64-аудио | максимум 700 000 символов |
| Timeout Gemini | 20 секунд на модель |
| Общий тайм-аут HTTP в обоих UI | 110 секунд, с учётом повторного разбора и поиска мест |
| Запросы одного клиента | 6 в минуту |
| Все фактические вызовы Gemini одного процесса, включая повторные/tool-вызовы | 30 в минуту |
| In-memory cache текста | до 1 часа, максимум 300 записей |

Успешно разрешённые текстовые формы без времени кешируются с учётом языка интерфейса. Голос и неясные ответы не кешируются. Запросы со временем вроде «через 20 минут» не кешируются.

Уточнение по privacy: текст и аудио не пишутся в файл, базу или application log. Нормализованный текст текстового запроса временно используется как ключ in-memory cache процесса до одного часа. Аудио в cache не сохраняется.

Backend последовательно пробует модели из `GEMINI_MODEL`. По умолчанию:

```text
gemini-3.5-flash-lite
gemini-3.6-flash
```

Если первая недоступна, исчерпала квоту, не поняла запрос или вернула missing/ambiguity, используется следующая. При голосовом вводе Flash получает уже распознанный `heard` как текст (если транскрипция есть), а исходная транскрипция сохраняется для UI. Старые значения `GEMINI_MODEL=gemini-flash-lite-latest,gemini-flash-latest` автоматически заменяются этими фиксированными ID, поэтому редактировать существующий `.env` не требуется.

Для оставшихся неразрешённых маршрутных запросов запускается Function Calling с двумя заранее объявленными функциями:

- `search_places(query?, category?, reference_id?, direction?, limit?, side?)`: поиск по `places.json.gz`; максимум 5 мест в ответе. `side` — from/to для сохранения кандидатов при сбое следующего вызова модели. Направления north/south/east/west проверяются локально по координатам относительно публичного `reference_id`. При reference результаты сортируются по расстоянию. Текущее положение посетителя в эту функцию модели не передаётся. Приближённые варианты и переход от ненайденного имени к категории имеют `requires_confirmation: true`; backend не разрешает молча превратить их в выбранную точку.
- `submit_route(...)`: завершить разбор и вернуть поля формы. Функция не строит маршрут и не исполняет произвольный код. Переданные ID проверяются по каталогу и уже выданным поисковым результатам.

Каталог берётся из существующего индекса; отсутствующие ориентиры не добавляются из памяти модели. RO/EN/RU-алиасы заданы в `backend/ask_places.py`. Простые запросы обычно занимают один вызов Lite. Неясные: ещё один Flash, затем при необходимости до трёх tool-раундов и четырёх поисковых функций. Последний раунд разрешает только submit_route. Сигнатуры мыслей Gemini сохраняются при продолжении tool-диалога. Неизвестные функции, выдуманные ID и слишком длинные цепочки отклоняются. При ошибке необязательного поиска возвращается частичная форма для ручного выбора.

`from_query`/`to_query` сохраняют исходные фразы до нормализации Gemini. Цитаты проверяются по тексту/транскрипции; для распространённых конструкций «от…до…», from…to…, de la…la… есть локальное выделение A/B. Точное имя или известный алиас из исходной фразы имеет приоритет над другим местом, подставленным моделью. Добавлены Căi/Căile Ferate, Railway Hospital, Parcul Botanic и разговорные русские названия. Приближённый поиск использует сравнение строк и ограниченную RO/RU/EN-эвристику звучания. Это ранжирование подсказок, не гарантия правильного распознавания речи. Неуверенный медицинский объект требует подтверждения; скульптура с именем врача не становится кандидатом больницы.

Если у всех неразрешённых сторон уже есть локальные варианты, дополнительных tool-вызовов нет. Исключение — пространственное условие, которое ещё нужно проверить поиском. Собранные кандидатуры сохраняются и при timeout/исчерпании бюджета следующего вызова.

Проверка backend без сети: `.venv/bin/python -m pytest backend/tests/test_ask.py backend/tests/test_ask_grounding.py backend/tests/test_ask_places_evidence.py -q`.

Проверка обоих UI: `scripts/testing/check_gemini_ui.cjs` (Playwright + установленный Chrome, свежий backend на localhost:8019). Ответы Gemini подменены fixtures, маршруты считает настоящий локальный backend, микрофон получает синтетический звук Chrome. Внешние ресурсы блокируются, Google не вызывается. Проверяются режим/дата, независимые A/B, выбор обеих точек, свежая геолокация, off-topic и запись mono WAV 16 кГц.

## 10. Состояния интерфейса

Минимальная state machine блока:

```text
idle
 ├─ submit text ───────────────→ sending
 └─ start mic → recording → encoding → sending

sending
 ├─ route ──────→ apply route → idle
 ├─ off_topic ──→ warning ─────→ idle
 ├─ unclear ────→ hint ────────→ idle
 ├─ not_found ──→ focus field ─→ idle
 ├─ clarify ────→ choose candidate → apply route / clarify remaining
 └─ HTTP error ─→ fallback ────→ idle
```

Во время `sending`:

- отключить submit и микрофон;
- не разрешать второй параллельный запрос;
- показать нейтральный статус «Разбираю запрос…»;
- в `finally` всегда вернуть кнопки в рабочее состояние.

Во время записи:

- заменить иконку микрофона на Stop;
- поставить `aria-pressed="true"`;
- разрешить остановку повторным нажатием;
- автоматически остановиться через 10 секунд;
- после остановки обязательно остановить все tracks микрофона.

## 11. Локализация

Backend понимает запросы не только на RO/EN/RU, но `lang` официально должен соответствовать языку интерфейса:

```text

en
ru
```

Все пользовательские сообщения формируются интерфейсом, не Gemini. Готовые переводы сейчас находятся в начале `web/ask.js` в `I18N.ro.ask`, `I18N.en.ask`, `I18N.ru.ask`.

Обязательные группы текстов:

- placeholder и label;
- начать/остановить запись;
- listening / thinking;
- understood / heard;
- off-topic;
- unclear;
- not-found;
- rate limit;
- provider unavailable;
- microphone denied;
- silence;
- privacy disclosure.

## 12. Privacy-текст

Возле формы должен быть явно видимый текст. Текущая русская версия:

```text
Текст или запись голоса отправляется в Google Gemini, чтобы понять запрос; мы не сохраняем их постоянно.
```

Более полная версия для tooltip/details:

```text
Gemini используется только для выделения места отправления, назначения, режима и времени. Маршрут рассчитывает Bloom. Координаты пользователя не отправляются Gemini. Текст и аудио не записываются в базу или файлы; текстовый запрос может до одного часа находиться в оперативной памяти backend как ключ кеша.
```

## 13. Зависимости существующего `web/ask.js`

Общий движок `BzAsk` требует `I18N`, `t`, `LANG`; его API:

## 14. Рекомендуемый универсальный обработчик ответа

Псевдокод, который нужно адаптировать к состоянию новой карты:

```js
async function interpretRoute(payload) {
  setAskState({ status: 'sending' });

  try {
    const response = await fetch('/api/ask', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        ...payload,
        lang: currentLanguage,
        near: startPoint ? `${startPoint.lat},${startPoint.lon}` : '',
      }),
    });

    const body = await response.json().catch(() => ({}));

    if (!response.ok) {
      const code = body?.detail?.code;
      showAskError(code === 'too_many' ? 'tooMany' : 'unavailable');
      return;
    }

    if (body.kind === 'off_topic') {
      showOffTopic(body.heard);
      return;
    }

    if (body.kind === 'unclear') {
      showUnclear(body.heard);
      return;
    }

    if (body.kind === 'not_found') {
      if (body.from) setStart(body.from);
      setUnresolvedField(body.which, body.name);
      focusAndOpenSuggestions(body.which);
      return;
    }

    if (body.kind !== 'route') {
      showAskError('unavailable');
      return;
    }

    if (body.mode) setMode(body.mode);
    if (body.at) setDeparture(body.at);
    setDestination(body.to);

    if (body.from) {
      setStart(body.from);
      recalculateRoute();
    } else if (startPoint && !body.from_here) {
      recalculateRoute();
    } else {
      locateUserAndRecalculate();
    }

    showUnderstood(body);
  } catch {
    showAskError('unavailable');
  } finally {
    setAskState({ status: 'idle' });
  }
}
```

## 15. Минимальный acceptance checklist нового UI

- [ ] Блок показывается только при `/api/health.ask === true`.
- [ ] Текстовый запрос заполняет A/B и запускает существующую маршрутизацию.
- [ ] Неназванный mode не сбрасывает выбранный режим.
- [ ] Запрос «отсюда» использует геолокацию.
- [ ] Запрос «до ближайшей аптеки» передаёт текущую A через `near`.
- [ ] `off_topic` не показывает свободный ответ модели.
- [ ] `not_found` переводит пользователя в обычный поиск места.
- [ ] Во время запроса нельзя отправить второй.
- [ ] Микрофон скрыт без HTTPS/MediaRecorder.
- [ ] Запись автоматически заканчивается через 10 секунд.
- [ ] Тихая запись не отправляется.
- [ ] После записи tracks микрофона остановлены.
- [ ] Ошибка Gemini не ломает ручные From/To и построение маршрута.
- [ ] Privacy-текст виден до отправки.
- [ ] API key отсутствует в frontend-коде и network response.
- [ ] Проверены RO, EN и RU.
