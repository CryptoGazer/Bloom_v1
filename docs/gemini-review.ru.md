# Повторная проверка Gemini — 15.11.2026

Изменения локальные. Коммит, push, деплой и перезапуск вашего процесса на 8001 не выполнялись. Тесты браузера запускались на отдельном localhost:8019.

Расширенный прогон 15 неочевидных сценариев после этого аудита выявил **4 проблемы**, не покрытые первоначальными smoke-тестами: см. `docs/testing/gemini-niche-15.ru.md` и полные JSON-ответы рядом. Успешная отрисовка маршрута сама по себе не подтверждает правильность интерпретации названия места.

## Общая концепция

Десктоп `/` и интерфейс Тимура `/m/` используют один `web/ask.js` и один endpoint `/api/ask`. Gemini извлекает поля и при необходимости вызывает локальный поиск. Индекс проверяет места; координаты берутся только из него. Расчёт пути выполняет `/api/route`. Результат неоднозначного запроса — уточнение, а не самовольный выбор похожей точки.

## Что исправлено при повторном аудите

1. Исходные фразы A/B сохраняются отдельно от нормализованных моделью названий. Нельзя потерять «Ботанический парк» из-за ошибки в больнице. Проверенное исходное имя имеет приоритет над ошибочным исправлением Gemini.
2. Добавлены варианты Căi/Căile Ferate, Railway Hospital и Parcul Botanic. Приближённый поиск и небольшая эвристика кириллического произношения ранжируют реальные места. Неуверенные результаты требуют выбора пользователем.
3. Переход поиска от ненайденного имени к категории явно помечается `requires_confirmation`. Gemini не может молча выбрать первую попавшуюся больницу. Типы фильтруются: памятник Pius Brînzeu не считается больницей.
4. Кандидаты, полученные поиском, сохраняются при timeout следующего вызова. Если локальных вариантов уже достаточно, лишний вызов Gemini не нужен.
5. Оба UI очищают координаты неразрешённых сторон и старый маршрут. Уже найденная сторона сохраняется. Запоздавший ответ старого расчёта не заменяет новый маршрут.
6. Явное «отсюда» сбрасывает прежнюю A перед геолокацией. Режим и полная дата отправления одинаково применяются в обоих интерфейсах.
7. `ask_version: 2` в `/api/health` позволяет отличить новый backend от старого процесса с обновлёнными файлами frontend.

## Проверки

Финальный результат аудита: **208 backend-тестов прошли**, по 6 браузерных сценариев в каждом интерфейсе прошли. Дополнительно живой сценарий из скриншота проверен через оба интерфейса с настоящим Gemini: выбор Căi Ferate построил маршрут в Parcul Botanic без второго `/api/ask`. Русская синтетическая запись через реальный Gemini вернула Parcul Botanic и правильную больницу среди кандидатов.

Дополнительная проверка именно перехода Gemini → маршрут: в обоих интерфейсах подтверждены запрос `/api/route` с фактическими координатами A/B, HTTP 200, непустая геометрия, видимая линия Leaflet и видимые карточки. Недостаточно одного `plan !== null`. В общих браузерных регрессиях проверено по четыре реально отрисованных маршрута на интерфейс, в том числе после голосового ввода и выбора двух кандидатов.

С настоящим Gemini отдельно прошли все четыре сочетания (два маршрута × два интерфейса):

| Маршрут | Десктоп `/` | Мобильный `/m/` | Быстрый пеший маршрут |
|---|---|---|---|
| Căminul C12 UVT → Piața Victoriei, прямой ответ Gemini | HTTP 200, линия и карточки видны | HTTP 200, линия и карточки видны | 1573,7 м; 19,4 мин |
| Spitalul Clinic Căi Ferate → Parcul Botanic, после уточнения больницы | HTTP 200, линия и карточки видны | HTTP 200, линия и карточки видны | 1605,4 м; 19,8 мин |

Эту живую проверку можно повторить вручную: `NODE_PATH=/tmp/bezna-gemini-ui/node_modules node scripts/testing/check_gemini_routes_live.cjs`. Нужен свежий backend на localhost:8019 с ключом Gemini. Скрипт использует настоящую модель и расходует API-квоту, в отличие от `check_gemini_ui.cjs`.

Backend, без Google:

```bash
.venv/bin/python -m pytest backend/tests -q
```

Браузерные сценарии, одинаковые для десктопа и мобильного экрана 390×844:

- режим велосипеда и полная дата отправления;
- новая B сохраняется при ненайденной A, старые координаты A удаляются;
- последовательный выбор двух неоднозначных точек без второго `/api/ask`;
- получение свежей геолокации при существующей A;
- off-topic не меняет текущий маршрут;
- MediaRecorder → mono WAV 16 кГц с синтетическим звуком Chrome.

Для воспроизведения нужен установленный Google Chrome и Playwright. В отдельном терминале:

```bash
TIGER_HISTORY=off .venv/bin/uvicorn backend.app:app --host 127.0.0.1 --port 8019
```

Сам Playwright можно установить в отдельную временную папку, без изменения production-зависимостей проекта:

```bash
npm install --prefix /tmp/bezna-gemini-ui playwright
NODE_PATH=/tmp/bezna-gemini-ui/node_modules node scripts/testing/check_gemini_ui.cjs
```

В этих браузерных проверках ответы Gemini заменены fixtures, внешний интернет блокируется; реальную маршрутизацию выполняет локальный backend. Микрофон получает синтетический звук, реальная речь не записывается.

Отдельно выполнены реальные запросы Gemini: искажённое название из скриншота, Căile Ferate, смешанный румынский запрос и русская синтетическая запись про больницу/Ботанический парк. Точное/известное имя даёт маршрут, неуверенное — выбор больницы с сохранённой B. Это проверка отдельных примеров, не гарантия любого акцента и шума; iOS Safari на физическом телефоне не проверялся.

## Файлы для ревью перед коммитом

- `backend/ask.py`, `backend/ask_places.py`: разбор, исходные названия, повторные вызовы, поиск и проверка кандидатов.
- `backend/app.py`: общий endpoint и версия в healthcheck.
- `web/ask.js`: один контроллер для обоих UI.
- `web/app.js`, `web/m/m.js`: одинаковые адаптеры очистки точек/маршрута и защита от устаревших ответов.
- `web/index.html`, `web/m/index.html`: разметка и стили выбора кандидатов.
- `.env.example`, `backend/README.md`, `docs/gemini-ui-integration.ru.md`: конфигурация и контракт.
- `backend/tests/test_ask.py`, `backend/tests/test_ask_grounding.py`, `backend/tests/test_ask_places_evidence.py`, `scripts/testing/check_gemini_ui.cjs`: регрессии.
- `scripts/testing/check_gemini_routes_live.cjs`: ручная сквозная проверка настоящего Gemini, route API и отрисовки в обоих UI.

В рабочем дереве также уже есть отдельные изменения Tiger Data, истории транспорта и логгера, в том числе в общих файлах. Для отдельного Gemini-коммита выбирайте соответствующие фрагменты через `git add -p`; `git add .` захватит и остальную работу. API-ключи и `.env` не менялись.
