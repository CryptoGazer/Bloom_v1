# Бэкенд: освещённость области и маршруты

Добавлено 14.11.2026 (пункты 1 и 2 из `PLAN.md`). Вечером 14.11 область сужена до университетского района и центра. Две части:

1. **Сборка** (`build_city.py`): для каждого отрезка пешеходной и велосети области считает статус освещённости. Область — `config/area.geojson`: прямоугольник модельного района к югу от Беги вместе с районом Cetate, 4,7 км². Само правило статуса — в `rules.py` (разделы 5–7 спецификации), его проверяет таблица согласованных случаев в `tests/test_rules.py`.
2. **API-сервер** (`app.py`, `routing.py`): держит граф области в памяти, строит маршруты и отдаёт отрезки для видимой части карты.

## Запуск

```bash
./scripts/mac/lightmap.sh setup   # один раз: окружение и зависимости (backend/requirements.txt)
./scripts/mac/lightmap.sh city    # сборка области → data/out/city/  (около 2 минут в первый раз, дальше секунды)
./scripts/mac/lightmap.sh api     # сервер на http://localhost:8001
./scripts/mac/lightmap.sh test    # тесты
```

Сборку нужно повторять, только если изменились данные или правила: готовые файлы `data/out/city/` уже лежат в проекте. Папка называется `city` по истории, внутри — область, а не весь город. Другой порт: `PORT=9000 ./scripts/mac/lightmap.sh api`.

Весь город, если понадобится (в отдельную папку, бэкенд читает её через `LIGHTMAP_SEGMENTS`):

```bash
.venv/bin/python -I backend/build_city.py --area config/city_boundary.geojson --out data/out/city-full
LIGHTMAP_SEGMENTS=data/out/city-full/segments.geojson.gz ./scripts/mac/lightmap.sh api
```

Попробовать запросы руками, без кода: http://localhost:8001/docs

## Что отдаёт сервер

| Запрос | Что возвращает |
|---|---|
| `GET /api/route?from=lat,lon&to=lat,lon` | два пеших маршрута, `fastest` и `better_lit`: минуты, метры, метры по статусам освещённости, предупреждение, улицы по ходу, геометрия кусками по статусу; `verdict` говорит, стоит ли показывать освещённый (`same` / `show` / `too_long`) |
| `GET /api/segments?bbox=west,south,east,north` | отрезки в окне карты (id, вид, название, длина, статус). Если их больше `limit` (по умолчанию 4000), список пустой и `truncated: true`: нужно приблизить карту или показать районы |
| `GET /api/segments/{id}` | один отрезок со свидетельствами: тег OSM, фонари Mapillary, жалобы, косвенные признаки |
| `GET /api/summary` | сводка: доли по статусам, проверки, таблица по 40 районам, источники с датами |
| `GET /api/health` | работает ли сервер и за какую дату данные |

Ошибки приходят с кодом в `detail.code`: `outside_coverage` (точка дальше 300 м от сети; в ответе расстояние до сети), `no_route`, `bad_point`, `bad_bbox`, `mode_not_supported`, `no_data`.

Сервер также раздаёт страницы `/demo/…` и `/data/out/…`, так что старые демо открываются с того же адреса. Остальные папки проекта (ключи, сырые данные) наружу не видны.

## Как строится маршрут

- Граф: отрезок — ребро от перекрёстка до перекрёстка, узлы — номера узлов OSM (`u`, `v`).
- Пешком нельзя: `foot=no` (проезжая часть бульваров, у которых тротуары нанесены отдельно), `access=no`, автомагистрали. Маршрут идёт только по самой большой связной части сети.
- Точка привязывается к ближайшему месту сети не дальше 300 м.
- Поиск A*: цена отрезка — длина × коэффициент статуса. Для быстрого маршрута все коэффициенты равны 1; для освещённого: освещено ×1,0, вероятно ×1,2, нет данных ×1,6, сообщали о темноте ×3,0.
- **Темнота маршрут не запрещает**, только делает дороже. Если к дому ведёт одна тёмная улица, маршрут пройдёт по ней и вернёт предупреждение.
- **Почти одинаковые маршруты показываются одной карточкой** (`verdict.kind = "same"`, `near: true`): освещённый маршрут добавляет меньше 5% подтверждённо освещённой длины и убирает меньше 5% длины «нет данных» и «темно». Исключение — он убирает тёмный кусок длиннее 100 м: тогда показываются оба.
- Все числа — в `SETTINGS` в начале `routing.py`.

## Файлы

| Файл | Что это |
|---|---|
| `backend/build_city.py` | сборка: сеть улиц (osmnx, кеш в `data/cache/city/`) + фонари + жалобы → статусы |
| `backend/rules.py` | правило статуса отрезка: чистые функции, без файлов и геометрии |
| `backend/routing.py` | граф, привязка точки, маршруты, выборка по окну; без веб-кода |
| `backend/app.py` | HTTP-обёртка на FastAPI |
| `backend/tests/test_routing.py` | 14 тестов маршрутов и API на маленькой рукотворной сети |
| `backend/tests/test_rules.py` | 32 теста: таблица из 18 согласованных случаев, склейка жалоб, разметка рукотворного квартала |
| `config/area.geojson` | область карты: модельный район и Cetate, 4,7 км² |
| `config/city_boundary.geojson` | граница города (OSM, relation 6927733, упрощена до ~10 м); для сборки всего города |
| `data/out/city/segments.geojson.gz` | результат: 5 405 отрезков области со статусами и свидетельствами, 0,3 МБ |
| `data/out/city/summary.json` | сводка, граница области, таблица по районам (`inside` — доля района внутри области) |

## Состояние данных на 14.11.2026

- Улицы и тротуары области, 113 км: освещение подтверждено у 63,2%, вероятно у 23,6%, сообщали о темноте у 1,2%, нет данных у 11,9%. Порог спецификации «нет данных не больше трети» выполнен.
- Дорожки в парках и кампусе, 62 км: нет данных у 42%. Это показываем как есть.
- Для сравнения, весь город (сборка до сужения): улицы и тротуары 873 км, нет данных у 38%, порог не выполнен; на окраинах данных мало.

## Проверено

- После выноса правила в `rules.py` старая и новая сборка дали одинаковый результат на всех 30 105 отрезках города.
- На модельном районе сборка даёт те же проценты, что черновая карта Тимура, по всем группам.
- Маршруты Python совпали с маршрутами браузерного демо (`demo/route/route.js`) на 294 случайных парах точек, расхождение до 0,2 м.
- Маршрут через весь город считается за 13 мс (медиана), до 70 мс.

## Известные упрощения

- Жалоба привязывается к одной ближайшей улице. Спор на перекрёстке по названию улицы не решаем: так решила команда 14.11.2026.
- Только пешком. Велосипед, транспорт и фильтры — следующие пункты плана.
- Расстояния считаются в плоской проекции с постоянными коэффициентами; ошибка по городу меньше 0,1%.

## Как удалить

```bash
rm -rf backend config/area.geojson config/city_boundary.geojson data/out/city data/cache/city
```

И убрать команды `city`, `api`, `test` из `scripts/mac/lightmap.sh`. Демо в `demo/` от бэкенда не зависят.
