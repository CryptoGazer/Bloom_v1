# Бэкенд: освещённость области и маршруты

Добавлено 14.11.2026 (пункты 1 и 2 из `PLAN.md`). Вечером 14.11 область сужена до университетского района и центра. Две части:

1. **Сборка** (`build_city.py`): для каждого отрезка пешеходной и велосети области считает статус освещённости. Область — `config/area.geojson`: прямоугольник модельного района к югу от Беги вместе с районом Cetate, 4,7 км². Само правило статуса — в `rules.py` (разделы 5–7 спецификации), его проверяет таблица согласованных случаев в `tests/test_rules.py`.
2. **API-сервер** (`app.py`, `routing.py`): держит граф области в памяти, строит маршруты и отдаёт отрезки для видимой части карты.

## Запуск

```bash
./scripts/mac/lightmap.sh setup   # один раз: окружение и зависимости (backend/requirements.txt)
./scripts/mac/lightmap.sh city    # сборка области → data/out/city/  (около 2 минут в первый раз, дальше секунды)
./scripts/mac/lightmap.sh api     # сервер на http://localhost:8001
./scripts/mac/lightmap.sh test    # тесты
```

Сборку нужно повторять, только если изменились данные или правила: готовые файлы `data/out/city/` уже лежат в проекте. Папка называется `city` по истории, внутри — область, а не весь город. Другой порт: `PORT=9000 ./scripts/mac/lightmap.sh api`.

### Gemini: запрос маршрута текстом или голосом

Скопировать `.env.example` в `.env` и записать ключ Google AI Studio в `GEMINI_API_KEY`. SDK не нужен: сервер вызывает Gemini REST API стандартной библиотекой Python. `GEMINI_MODEL` необязателен; по умолчанию сервер пробует `gemini-flash-lite-latest`, затем `gemini-flash-latest`.

После перезапуска `GET /api/health` возвращает `"ask": true`, а над полями адресов появляется строка естественного языка и кнопка микрофона. Голос пишет браузер, преобразует запись в mono WAV 16 кГц и отправляет её тому же `/api/ask`; ElevenLabs для этого не используется.

Gemini не строит маршрут и не пишет ответ пользователю. Он заполняет фиксированную JSON-форму: intent, откуда, куда, режим и локальное время. Названия затем ищутся только в нашем `places.json.gz`, а сам маршрут считает `routing.py`. Рецепты, программирование, общие вопросы, запросы про другие города и prompt injection получают `kind: "off_topic"`. Текст или аудио уходит в Google, но не сохраняется нашим сервером; координаты в Gemini не отправляются.

### Live-транспорт: CSV и Tiger Data

```bash
./scripts/transit/logger.sh start 6       # до следующего 04:05 Europe/Bucharest
./scripts/transit/logger.sh status
./scripts/transit/logger.sh log
./scripts/transit/logger.sh sync-tiger    # безопасно повторять: догрузка всего CSV
./scripts/transit/logger.sh stop
```

Локальный журнал `data/transit/vehicles.csv` и `polls.csv` всегда записывается и синхронно сбрасывается на диск первым. Если в `.env` есть `TIGER_DATABASE_URL`, тот же poll одной транзакцией отправляется в hypertable `transit_vehicle_fixes` и `transit_polls`. Ключ GPS-фикса — `(vehicle_id, fix_at)`, поэтому повторы городской API и повторный `sync-tiger` пропускаются. Ошибка Tiger не останавливает сбор: логгер продолжает CSV, повторяет подключение раз в 30 секунд, а пропуск затем закрывает `sync-tiger`.

`transit_vehicle_fixes` содержит типизированную историю координат, маршрута, рейса, остановки, скорости и задержки. `transit_polls` хранит доступность и свежесть источника. Сейчас FastAPI эти таблицы ещё не читает: подключение live API, replay и агрегатов — отдельный этап, чтобы база не стала зависимостью существующей маршрутизации.

Весь город, если понадобится (в отдельную папку, бэкенд читает её через `LIGHTMAP_SEGMENTS`):

```bash
.venv/bin/python -I backend/build_city.py --area config/city_boundary.geojson --out data/out/city-full
LIGHTMAP_SEGMENTS=data/out/city-full/segments.geojson.gz ./scripts/mac/lightmap.sh api
```

Попробовать запросы руками, без кода: http://localhost:8001/docs

## Что отдаёт сервер

| Запрос | Что возвращает |
|---|---|
| `POST /api/ask` | Понимает текст (`text`) или короткий base64-аудиофайл (`audio`, `mime`) на румынском, английском или русском; возвращает `route` с точками из локального индекса, `not_found`, `unclear` или `off_topic`. Лимиты: 300 символов, запись интерфейса до 10 секунд, 6 запросов в минуту с одного клиента |
| `GET /api/route?from=lat,lon&to=lat,lon&mode=walk` | `mode=walk` (по умолчанию), `mode=bike` или `mode=transit` (пешком + транспорт; `at=HH:MM` или `YYYY-MM-DDTHH:MM` — время выхода, иначе сейчас; в ответе `transit`: шаги поездки, последний рейс или причина, почему поездки нет); два маршрута, `fastest` и `better_lit`: минуты, метры, метры по статусам освещённости, предупреждение, улицы по ходу, геометрия кусками по статусу; `verdict` говорит, стоит ли показывать освещённый (`same` / `show` / `too_long`) |
| `GET /api/geocode?q=camin c12&limit=8` | подсказки для полей адреса: улицы, адреса с номером дома, места, остановки внутри области; `number_missing`, если такого номера нет на карте. Индекс — `data/out/city/places.json.gz` от `backend/build_places.py` (адреса и места из Overpass, кеш в `data/cache/places/`) |
| (в ответе `/api/route`) `routes.*.signs` | признаки жизни по пути на время `at` (по умолчанию сейчас): `open_places` — открытые места с людьми в 50 м (часы из OSM), `places_unknown_hours`, `stops` — остановки в 100 м с рейсами в ±10 мин, `main_share` — доля пути по главным улицам. Модуль `backend/liveliness.py`, оценки нет |
| `GET /api/segments?bbox=west,south,east,north` | отрезки в окне карты (id, вид, название, длина, статус). Если их больше `limit` (по умолчанию 4000), список пустой и `truncated: true`: нужно приблизить карту или показать районы |
| `GET /api/segments/{id}` | один отрезок со свидетельствами: тег OSM, фонари Mapillary, жалобы, косвенные признаки |
| `GET /api/summary` | сводка: доли по статусам, проверки, таблица по 40 районам, источники с датами |
| `GET /api/health` | работает ли сервер и за какую дату данные |

Ошибки приходят с кодом в `detail.code`: `outside_coverage` (точка дальше 300 м от сети; в ответе расстояние до сети), `no_route`, `bad_point`, `bad_bbox`, `mode_not_supported`, `no_data`.

Сервер также раздаёт страницы `/demo/…` и `/data/out/…`, так что старые демо открываются с того же адреса. Остальные папки проекта (ключи, сырые данные) наружу не видны.

## Как строится маршрут

- Граф: отрезок — ребро от перекрёстка до перекрёстка, узлы — номера узлов OSM (`u`, `v`).
- Пешком нельзя: `foot=no` (проезжая часть бульваров, у которых тротуары нанесены отдельно), `access=no`, автомагистрали. Маршрут идёт только по самой большой связной части сети.
- Точка привязывается к ближайшему месту сети не дальше 300 м.
- Поиск A*: цена отрезка — длина × коэффициент статуса. Для быстрого маршрута все коэффициенты равны 1; для освещённого: освещено ×1,0, вероятно ×1,2, нет данных ×1,6, сообщали о темноте ×3,0.
- **Темнота маршрут не запрещает**, только делает дороже. Если к дому ведёт одна тёмная улица, маршрут пройдёт по ней и вернёт предупреждение.
- **Когда выбирать не из чего, показывается одна карточка** (`verdict.kind = "same"`, `pick` — какой маршрут в ней): освещённый маршрут добавляет меньше 5% подтверждённо освещённой длины и убирает меньше 5% длины «нет данных» и «темно» — показывается быстрый (`pick: fastest`); освещённый не дольше быстрого больше чем на 30 секунд — показывается он один (`pick: better_lit`, «Более освещённый и не дольше»). Исключение из первого правила: освещённый убирает тёмный кусок длиннее 100 м.
- Все числа — в `SETTINGS` в начале `routing.py`.

## Состояние данных на 14.11.2026

- Улицы и тротуары области, 113 км: освещение подтверждено у 63,2%, вероятно у 23,6%, сообщали о темноте у 1,2%, нет данных у 11,9%. Порог спецификации «нет данных не больше трети» выполнен.
- Дорожки в парках и кампусе, 62 км: нет данных у 42%. Это показываем как есть.
- Для сравнения, весь город (сборка до сужения): улицы и тротуары 873 км, нет данных у 38%, порог не выполнен; на окраинах данных мало.

## Проверено

- После выноса правила в `rules.py` старая и новая сборка дали одинаковый результат на всех 30 105 отрезках города.
- На модельном районе сборка даёт те же проценты, что черновая карта Тимура, по всем группам.

## Известные упрощения

- Жалоба привязывается к одной ближайшей улице. Спор на перекрёстке по названию улицы не решаем: так решила команда 14.11.2026.
- Пешком и на велосипеде. Велосипед едет только там, где OSM разрешает (`bicycle`, `access`, тротуары — только с велознаком), по односторонним улицам — только по направлению движения, если нет встречной велополосы; участки `bicycle=dismount` считаются по скорости пешехода. Транспорт и фильтры — следующие пункты плана.
- Велосипедный граф в области: 2 898 отрезков (116,9 км) — самая большая сильно связная часть, где от любого перекрёстка можно доехать до любого другого с учётом односторонних улиц. 238 отрезков (10,7 км: односторонние тупики, дворовые проезды, улицы, обрезанные границей области) велосипеду не предлагаются: иначе 14–19% пар точек оставались без маршрута (проверено на 600 случайных парах; после исправления 0).
- Расстояния считаются в плоской проекции с постоянными коэффициентами; ошибка по городу меньше 0,1%.

## Как удалить

```bash
rm -rf backend config/area.geojson config/city_boundary.geojson data/out/city data/cache/city
```

И убрать команды `city`, `api`, `test` из `scripts/mac/lightmap.sh`. Демо в `demo/` от бэкенда не зависят.
